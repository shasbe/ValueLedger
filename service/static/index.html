What's worth looking at

  • Coverage is two numbers, never one. Classification ~96%, cost ~87%. The gap is chat: it can be classified but not priced, because the model cannot see its own token usage. Collapsing these into one number would hide exactly the thing a CFO needs to know.
  • Dark spend. Money on sessions that produced no durable artifact — ~19% here. Requires cost and outcomes joined at session grain, which nothing in a normal FinOps stack has.
  • Productivity is the one modelled metric, and says so. 1.59× — but the range is 0.82×–3.21×, and the low end falls below 1×. The UI leads with that rather than the midpoint. Change a baseline on the Productivity tab and every number moves.
  • Classification overhead, self-metered. 0.13% of tracked spend. A cost-control tool that quietly costs money is self-defeating, so it meters itself in public.
  • Try to break the MCP trust boundary. Publish an attribution naming an initiative that doesn't exist, or claiming a different user and a cost — the initiative is refused, and identity and cost come from the token, never the payload.
  • Switch roles and watch the numbers change. A member asking for another user's rows gets their own back — filtered server-side, not hidden in the UI.
All data is synthetic — 1,070 sessions across 6 initiatives, 40 users, 4 cost centers, 90 days. Costs are reconstructed from public list prices, so they will not match any real invoice.
